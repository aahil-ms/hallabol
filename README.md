## 🤖 How the Machine Learning Works

### Algorithm: Random Forest Regressor

A Random Forest is a collection of 300 decision trees that vote together to make predictions. Each tree learns a slightly different version of the data, and the final answer is the average — this makes it very robust.

### Training Pipeline

```
Raw ball-by-ball data
        │
        ▼
Feature Engineering (15 features per player)
        │
        ▼
Expert Score Label (domain-knowledge formula → 0-100)
        │
        ▼
Random Forest trains on Features → predicts Expert Score
        │
        ▼
Cross-Validation (5-fold R² ≈ 0.97) confirms accuracy
        │
        ▼
"SupeRR Score" = model's prediction for every player
```

### Why Not Pure ML (without labels)?

The data has no "this player was selected / not selected" column.
So we:
1. Use **expert cricket knowledge** to define what a good score looks like
2. The model learns the **interaction patterns** between features
3. This generalises far better to new players than a simple formula

### Key Metrics Used

| Batting | Bowling |
|---------|---------|
| Strike Rate | Economy Rate |
| Batting Average | Bowling Average |
| Boundary % | Bowling Strike Rate |
| Phase SR (PP / Mid / Death) | Phase Economy (PP / Mid / Death) |
| Consistency % | Dot Ball % |
| 50+ / 30+ scores | 3-wkt / 5-wkt hauls |

## 📝 Notes

- Players with < 30 balls faced are excluded from batting model
- Players with < 24 balls bowled (4 overs) are excluded from bowling model
- Run-outs are NOT credited to bowlers
- Wide and no-ball deliveries are excluded from legal ball counts for SR/economy
